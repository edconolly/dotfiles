# Generating directions

The point of several proposals is to compare *decisions*, not skins. Spread each set across three groups of
axes: **idea**, **form** and **personality**. Each group was learned the hard way on Bot Max:
- Round 1 varied only colour and fonts: nine proposals came out with the same corners, borders, controls, buttons
  and page layouts (one product in nine paints).
- Round 2 assigned form and layout, which fixed that, but personality was left free. Six of nine landed on
  light, cool, low-saturation greys; eight of nine on a plain grotesque sans; seven of nine on the same status
  colours; and all nine wrote in the same voice. Unassigned axes drift to one model's taste.

## Idea axes
| Axis | Options |
|---|---|
| Idea / positioning | A different promise the product can actually make (from the user's notes, or proposed and marked as a hypothesis) |
| Brand ↔ product model | One unified / one foundation, two expressions / separate systems (anatomy.md §4) |
| Audience lens | e.g. self-serve SMB vs enterprise (security review, audits, roles, SLAs, procurement) |
| Mood and material | A metaphor from the subject's world: an instrument, a case file, a venue door, a till slip, a map, a stage, a ledger, a signal box, a risk report… |
| Signature idea | The one memorable component used at every size, ideally one that does a real job (a receipt, a map, a stamp, an incident timeline) |
| Market position | How it looks different from the competitors in the audit (step 2 of SKILL.md), in one line |

## Form axes (no two directions may share more than two)
| Axis | Options |
|---|---|
| Corners | sharp 0 · small 2–6 · soft 10–16 · round pill · mixed by role |
| Edges | hairlines · heavy rules 2–4 px · filled tonal blocks, no borders · depth by shadow/layering |
| Density | compact (rows 24–26) · medium (32–36) · roomy (44–48) |
| Button construction | filled block · text with underline · pill · bordered tile with icon · segmented bar |
| Status construction | dot + word · filled tag · letter cell · outlined stamp · bar in the row · large numeral |
| Product layout | single column feed · sidebar + content · split panes · canvas/map · timeline-first · document/register |
| Website composition | centred statement · full-bleed product image · editorial long-read · interactive demo first · data story · comparison table first |
| Scale contrast | flat (headline ≈1.5× body) · dramatic (≈5× body) |

## Personality axes (spread these too)
| Axis | Bands | Spread rule |
|---|---|---|
| Colour mood | light neutral (white/grey/off-white) · light tinted (a coloured ground) · mid-tone (a saturated or deep ground for the brand) · dark neutral · dark tinted · high-contrast black and white | No band holds more than a third of the set (round up). Name the band and the ground hex for each direction |
| Lead type class | grotesque/neo-grotesque sans · humanist sans · geometric sans · serif (text or display) · slab · monospace-led · condensed/display | No two directions share the class of their lead face. A second face may repeat a class |
| Tone of voice | e.g. expert witness, shopkeeper, signal-box radio, engineer's log, concierge, actuary, cartographer | Each direction gets a named tone and three sample lines (a headline, an error, a status message) written in it. Product truths (exact status words, claims we can't make) stay fixed in the brief; tone does not |

**Status colours are a decision, not an accident.** Before drafting, decide with the user: either the status
palette is **fixed** for all directions (values in the brief, e.g. kept from the current product or chosen once)
so proposals stay comparable on it, or it is **varied** on purpose (each direction designs its own, and the
review compares them). Write the choice into the brief. Don't leave it open: open, it converges.

**Logos are out of scope** until the name is final. Every direction uses a plain text wordmark (the name set in
its lead face) as a placeholder. Improvised marks add noise and suggest a brand that doesn't exist yet. Logo and
name work is separate identity work.

## Description format (show the user before building)
**Name** (one or two words)
**The idea**: 2–3 plain sentences the user can picture; what it feels like and why it fits the product.
- For (buyer, daily user) · Idea it carries · Website vs dashboard · Signature idea · (enterprise) Feature it must design for
- **Form**: corners · edges · density · button · status · product layout · website composition · scale
- **Personality**: colour mood band + 3–5 named hex colours · lead type class + families · tone + three sample lines
**How it differs**: from the others (at least one form *and* one personality difference) and from competitors (one line).

Keep a set under ~600 words. Draft with a subagent, then review it yourself before showing the user:
- Make one table of the set: form choices, colour mood band, lead type class, tone. Fix any direction that shares
  more than two form choices with another, any colour band holding more than a third, any repeated lead class.
- Flag generic colours (e.g. #F4F1EA cream), claims the product can't back, false "only one that…" lines, and real
  product or bot names described inaccurately.
- Then wait for the user to choose, edit or approve. Don't build from descriptions the user hasn't read.
