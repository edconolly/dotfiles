# Generating directions

The point of several proposals is to compare *decisions*, not skins. Three variants of one palette waste
everyone's time. Spread each set across several axes at once.

## Axes to vary
| Axis | Options |
|---|---|
| Idea / positioning | Each direction carries a different promise the product can actually make (take them from the user's positioning notes, or propose them and mark as hypotheses) |
| Brand ↔ product model | One unified / one foundation, two expressions / separate systems (see anatomy.md §4); give each direction a different one when there are three |
| Audience lens | e.g. self-serve SMB vs enterprise (security review, audits, roles, SLAs, procurement) |
| Mood and material | A metaphor from the subject's world: an instrument, a case file, a venue door, a till slip, a map, a stage, a ledger, a signal box, a risk report… |
| Theme | Light, dark, or both (a working switch proves the semantic tokens) |
| Density | Compact, medium, roomy; brand and product may differ |
| Type | Real, freely available families; assign them up front so builders don't converge; no family reused across a set |
| Colour strategy | e.g. colour only means data; one brand colour; colour encodes ownership; solid vs ghost layers; money-only accent |
| Signature idea | The one memorable component or pattern, used at every size (a reading on a scale, an evidence strip, an entry pass, a receipt, a boundary line, a ghost overlay, a custody stamp, incident mode, an exposure band) |
| Enterprise feature (if enterprise) | Role badges and read-only state, two-person approval, audit trail, incident/handover mode, tenant/scope switcher, export to slide or PDF |

## Description format (show the user before building)
**Name** (one or two words)
**The idea**: 2–3 plain sentences the user can picture; what it feels like and why it fits the product.
- For (buyer, daily user) · Idea it carries · Website vs dashboard · Light/dark · Type · 3–5 named hex colours ·
  Signature idea · (enterprise) Feature it must design for
**How it differs** from the others: one line.

Keep a set under ~450–500 words. Use a subagent to draft; then review it yourself before showing the user:
- Flag any colour that matches a generic look (e.g. #F4F1EA cream) and propose a change.
- Flag claims the product can't back (compliance, certifications, numbers it doesn't produce yet).
- Correct any "the only one that…" claims that are false against earlier directions.
- Then wait for the user to choose, edit or approve. Don't build from descriptions the user hasn't read.
