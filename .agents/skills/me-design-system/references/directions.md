# Generating directions

The point of several proposals is to compare *decisions*, not skins. Spread each set across surface axes
(colour, type, idea) **and form axes** (shape, edges, density, construction, layout). Surface-only variation is
what made nine Bot Max proposals look like one product: they differed in colour and fonts but all picked the
same corners, borders, control sizes, buttons and page layouts.

## Surface axes
| Axis | Options |
|---|---|
| Idea / positioning | A different promise the product can actually make (from the user's notes, or proposed and marked as a hypothesis) |
| Brand ↔ product model | One unified / one foundation, two expressions / separate systems (anatomy.md §4) |
| Audience lens | e.g. self-serve SMB vs enterprise (security review, audits, roles, SLAs, procurement) |
| Mood and material | A metaphor from the subject's world: an instrument, a case file, a venue door, a till slip, a map, a stage, a ledger, a signal box, a risk report… |
| Theme | Light, dark, or both |
| Type | Real, freely available families; assigned up front; no family reused across a set |
| Colour strategy | e.g. colour only means data; one brand colour; colour encodes ownership; solid vs ghost layers; money-only accent |
| Signature idea | The one memorable component used at every size |

## Form axes (assign these too; no two directions may share more than two)
| Axis | Options |
|---|---|
| Corners | sharp 0 · small 2–6 · soft 10–16 · round pill · mixed by role |
| Edges | hairlines · heavy rules 2–4 px · filled tonal blocks, no borders · depth by shadow/layering |
| Density | compact (rows 24–26) · medium (32–36) · roomy (44–48) |
| Button construction | filled block · text with underline · pill · bordered tile with icon · segmented bar |
| Status construction | dot + word · filled tag · letter cell · outlined stamp · bar in the row · large numeral |
| Product layout | single column feed · sidebar + content · split panes · canvas/map · timeline-first · document/register |
| Website composition | centred statement · full-bleed product image · editorial long-read · interactive demo first · data story · comparison table first |
| Scale contrast | flat (headline ≈1.5× body) · dramatic (≈5× body) |

Jobs, not screens: describe what the product screen and the website must achieve, and give each direction its
own layout idea for doing it. Signature components that do a real job (a receipt, a map, a stamp, an incident
timeline) are what make a direction look different in practice; prefer directions that need one.

## Description format (show the user before building)
**Name** (one or two words)
**The idea**: 2–3 plain sentences the user can picture; what it feels like and why it fits the product.
- For (buyer, daily user) · Idea it carries · Website vs dashboard · Light/dark · Type · 3–5 named hex colours ·
  Signature idea · (enterprise) Feature it must design for
- **Form**: corners · edges · density · button · status · product layout · website composition
**How it differs** from the others: one line, naming at least one form difference, not only colour.

Keep a set under ~500 words. Draft with a subagent, then review it yourself before showing the user:
- Make a small table of the set's form profiles; if two directions share more than two form choices, change one.
- Flag generic colours (e.g. #F4F1EA cream), claims the product can't back, false "only one that…" lines.
- Then wait for the user to choose, edit or approve. Don't build from descriptions the user hasn't read.
